# 去掉安卓端全面屏（edge-to-edge）状态栏适配的操作文档

## 1. 背景

为修复 Android 端顶部出现默认紫色状态栏、底部黑色导航栏、页面无法铺满全屏的问题，曾做过一套「全面屏（edge-to-edge）适配」。改动包含**原生层**（Tauri 生成的 Android 工程）与**前端层**（移动端 Vue 页面/CSS）两部分。

本文档说明如何**完整还原这些改动**，恢复到改动前的表现：顶部保留系统默认状态栏（含背景色），页面内容不再延伸到状态栏 / 导航栏之后。

> 还原后，Android 端会重新出现系统默认的状态栏颜色与导航栏区域，属于预期行为。

## 4. 方法二：手动还原（逐文件）

### 4.1 前端：index.html

移除 viewport 中追加的 `viewport-fit=cover`：

```html
<!-- 还原前 -->
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />
<!-- 还原后 -->
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

### 4.2 前端：theme.css

删除文件末尾追加的 `.van-nav-bar` 规则（连同其上方空行）：

```css
/* 删除以下内容： */

/* Edge-to-edge: let fixed nav bars sit below the status bar. */
.van-nav-bar {
  height: calc(46px + env(safe-area-inset-top));
  padding-top: env(safe-area-inset-top);
}
```

删除后文件以 `:root { ... }` 的收尾 `}` 结束即可（即原本最后一行是 `--van-field-placeholder-text-color: var(--text-placeholder);` 及其下的 `}`）。

### 4.3 前端：各页面 `.header` 安全区顶内边距

将下表文件中 `.header` 的内边距改回原值：

| 文件 | 还原前 | 还原后 |
| --- | --- | --- |
| `pages/Profile/index.vue` | `padding: max(16px, env(safe-area-inset-top)) 20px;` | `padding: 16px 20px;` |
| `pages/Chats/index.vue` | `padding: max(16px, env(safe-area-inset-top)) 20px 0;` | `padding: 16px 20px 0;` |
| `pages/Friends/index.vue` | `padding: max(16px, env(safe-area-inset-top)) 20px;` | `padding: 16px 20px;` |
| `pages/Plaza/index.vue` | `padding: max(16px, env(safe-area-inset-top)) 20px;` | `padding: 16px 20px;` |
| `pages/Plaza/feed/MomentDetail.vue` | `padding: max(12px, env(safe-area-inset-top)) 16px;` | `padding: 12px 16px;` |
| `pages/Friends/FriendDetail.vue` | `padding: max(16px, env(safe-area-inset-top)) 20px;` | `padding: 16px 20px;` |
| `pages/Friends/SearchFriend.vue` | 同上 | `padding: 16px 20px;` |
| `pages/Friends/Requests.vue` | 同上 | `padding: 16px 20px;` |
| `pages/Friends/GroupInvitations.vue` | 同上 | `padding: 16px 20px;` |

> 聊天单聊/群聊页（`pages/Chats/Chat/index.vue`、`pages/Chats/GroupChat/index.vue`）、`BottomNav`、`QuicStatusBar`、通话页等原本就带有 `env(safe-area-inset-*)`，不属于本次改动，还原时**不要**动它们。

### 4.4 原生：MainActivity.kt

文件：`src-tauri/gen/android/app/src/main/java/com/only/talk/app/MainActivity.kt`

删除 `onCreate` 中开启 edge-to-edge 的代码，恢复为最小实现：

```kotlin
// 还原前（含本次改动）
package com.only.talk.app

import android.os.Bundle
import androidx.core.view.WindowCompat
import androidx.core.view.WindowInsetsControllerCompat

class MainActivity : TauriActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        WindowCompat.setDecorFitsSystemWindows(window, false)

        val controller = WindowInsetsControllerCompat(window, window.decorView)
        controller.isAppearanceLightStatusBars = true
        controller.isAppearanceLightNavigationBars = true
    }
}
```

```kotlin
// 还原后
package com.only.talk.app

class MainActivity : TauriActivity()
```

### 4.5 原生：themes.xml（values 与 values-night）

- `src-tauri/gen/android/app/src/main/res/values/themes.xml`
- `src-tauri/gen/android/app/src/main/res/values-night/themes.xml`

删除 `<style>` 中追加的全部 `<item>`，恢复为空的自定义主题：

```xml
<!-- 还原前 -->
<resources xmlns:tools="http://schemas.android.com/tools">
    <style name="Theme.app" parent="Theme.MaterialComponents.DayNight.NoActionBar">
        <item name="android:windowBackground">@android:color/white</item>
        <item name="android:statusBarColor">@android:color/transparent</item>
        <item name="android:navigationBarColor">@android:color/transparent</item>
        <item name="android:windowLightStatusBar">true</item>
        <item name="android:windowLightNavigationBar">true</item>
        <item name="android:windowLayoutInDisplayCutoutMode">shortEdges</item>
    </style>
</resources>
```

```xml
<!-- 还原后 -->
<resources xmlns:tools="http://schemas.android.com/tools">
    <!-- Base application theme. -->
    <style name="Theme.app" parent="Theme.MaterialComponents.DayNight.NoActionBar">
        <!-- Customize your theme here. -->
    </style>
</resources>
```

> 说明：`values-night/themes.xml` 还原前的 `<item>` 内容比 `values` 少 `windowLightStatusBar / windowLightNavigationBar` 两项，删除 `<item>` 后同样还原为空主题即可。

## 5. 重新构建验证

还原完成后重新打包 Android 应用：

```powershell
# 前端检查（可选，确认无语法错误）
pnpm --filter @workspace/app-mobile build

# 打包 Android APK
pnpm tauri android build
```

构建产物一般为 `src-tauri/gen/android/app/build/outputs/apk/...`，重新安装到设备/模拟器后即可确认：

- 顶部重新出现系统默认状态栏（颜色随系统主题）；
- 底部重新出现导航栏区域；
- 页面内容不再延伸到系统栏之后。

## 6. 常见问题

**Q1：只想去掉顶部的紫色，但希望页面尽量铺满，怎么做？**
不删除原生改动，仅把 `themes.xml` 中 `android:statusBarColor` 由 `@android:color/transparent` 改成与页面顶部背景一致的颜色（如 `#ffffff`），可保留 edge-to-edge 的同时让状态栏视觉更协调。

**Q2：还原后底部黑边还在？**
底部区域属于系统导航栏。edge-to-edge 关闭后该区域颜色由主题的 `android:navigationBarColor` 决定，可在保留现有原生改动的前提下，把它改为 `@android:color/white` 或应用主色，而不是整体回退。

**Q3：重新执行过 `tauri android init` 后原生文件被重置怎么办？**
`gen/android` 由模板生成，若重新 init 会覆盖手工改动。若未来需要长期保留原生改动，建议通过初始化后的模板修改并在重生成后重新应用，或记录到本仓库文档中留存。

**Q4：前端还原后，聊天页等原本的安全区内边距还要保留吗？**
要保留。聊天单聊/群聊、底部导航、连接状态栏、通话页的 `env(safe-area-inset-*)` 是既有代码，与本次 edge-to-edge 适配无关，删除它们会影响 iPhone 全面屏等设备的表现。
