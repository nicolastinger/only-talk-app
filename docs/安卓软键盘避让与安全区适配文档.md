# 安卓软键盘避让与安全区适配（edge-to-edge）文档

> 适用范围：`only-talk-app`（Tauri 2 Android 端）
> 关键文件：`src-tauri/gen/android/app/src/main/java/com/only/talk/app/MainActivity.kt`
> `apps/mobile/src/utils/viewport.ts`

## 背景

移动端 WebView 是 edge-to-edge 布局（`WindowCompat.setDecorFitsSystemWindows(window, false)`），
页面铺满全屏，状态栏/底部导航的避让完全交给前端 CSS 的 `env(safe-area-inset-*)` 处理。
聊天页等大量页面依赖它，例如：

- 顶部标题：`padding-top: max(12px, env(safe-area-inset-top))`
- 底部输入栏：`padding-bottom: max(10px, env(safe-area-inset-bottom))`
- 全局底部导航（`BottomNav`）：`padding-bottom: env(safe-area-inset-bottom)`

问题点在于 **软键盘**：键盘弹出后输入框/页面底部需要被顶到键盘上方。

## 现象时间线

1. 最初只靠 `adjustResize`：键盘弹出后输入框被键盘遮挡，内容不上升（本机无效果）。
2. 在 `MainActivity` 监听 window insets，把 **全部** insets `CONSUMED` 并手动 `setPadding` 到底部 IME 高度：
   键盘能正常顶起内容了，**但** 状态栏/底部导航开始遮挡页面——因为整体 `CONSUMED`
   导致 WebView 收不到任何 systemBar insets，所有 `env(safe-area-inset-*)` 归零，页面安全区内边距塌陷。
3. 最终方案：**只消费 IME insets，保留并透传 systemBars insets**（见下）。两个问题同时解决。

## 根因

- 本设备在 edge-to-edge（`decorFitsSystemWindows=false`）下会**忽略 `adjustResize` 的窗口缩放**，
  因此必须手动消费 IME insets 才能顶起内容。
- 但若在根部把 insets 整体 `CONSUMED`，Android 不会再把它派发给 WebView，
  WebView 无法计算安全区，`env(safe-area-inset-*)` 全部返回 0 —— 顶部/底部栏于是压住内容。
- 全 App 几十处 CSS 都依赖该 env 值，吞掉 insets 是全局性破坏。

## 最终方案

### 原生侧 `MainActivity.kt`

```kotlin
package com.only.talk.app

import android.os.Bundle
import android.view.WindowManager
import androidx.core.graphics.Insets
import androidx.core.view.ViewCompat
import androidx.core.view.WindowCompat
import androidx.core.view.WindowInsetsCompat
import androidx.core.view.WindowInsetsControllerCompat

class MainActivity : TauriActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        window.setSoftInputMode(WindowManager.LayoutParams.SOFT_INPUT_ADJUST_RESIZE)

        // edge-to-edge：页面铺满全屏，状态栏/导航栏由前端 env(safe-area-inset-*) 处理
        WindowCompat.setDecorFitsSystemWindows(window, false)

        ViewCompat.setOnApplyWindowInsetsListener(window.decorView) { view, insets ->
            val imeBottom = insets.getInsets(WindowInsetsCompat.Type.ime()).bottom
            // 用 padding 模拟窗口被键盘顶起的效果
            view.setPadding(0, 0, 0, imeBottom)
            // 只吞掉 IME insets；systemBars 等其余 insets 继续下发给 WebView，
            // 保证 env(safe-area-inset-*) 仍能拿到状态栏/导航栏高度。
            WindowInsetsCompat.Builder(insets)
                .setInsets(WindowInsetsCompat.Type.ime(), Insets.NONE)
                .build()
        }

        val controller = WindowInsetsControllerCompat(window, window.decorView)
        controller.isAppearanceLightStatusBars = true
        controller.isAppearanceLightNavigationBars = true
    }
}
```

要点：

- `AndroidManifest.xml` 中 `<activity>` 需保持 `android:windowSoftInputMode="adjustResize"`，
  与代码里的 `setSoftInputMode` 一致。
- 键盘弹出：`imeBottom > 0` → 底部 padding = 键盘高度，页面被顶起；
- 键盘收起：`imeBottom == 0` → padding 归零，恢复沉浸式全屏；
- 返回值用 `WindowInsetsCompat.Builder(insets).setInsets(ime(), Insets.NONE).build()`
  清空 IME，但 statusBars / navigationBars 原样透传给 WebView → CSS 安全区照常工作。

### 前端配套 `apps/mobile/src/utils/viewport.ts`

聊天页根部元素（`.chat-page`）通过 `attachViewportHeight` 把高度绑定到“当前可见高度”：

```ts
export const getVisibleViewportHeight = (): number => {
  const vv = window.visualViewport;
  const inner = window.innerHeight;
  const vvHeight = vv ? vv.height : inner;
  // 键盘弹出时取较小值；异常时至少保留 200px，避免布局塌陷
  return Math.max(200, Math.min(inner, vvHeight));
};
```

兼容三种情况：

- Android adjustResize：`window.innerHeight` 变小；
- iOS / 沉浸式键盘：`visualViewport.height` 变小（innerHeight 不变）；
- 事件信号不稳定：`ResizeObserver` + `focusin/focusout` + 多次延时校正。

接入位置：单聊 `apps/mobile/src/pages/Chats/Chat/index.vue`、群聊
`apps/mobile/src/pages/Chats/GroupChat/index.vue`，在 `onMounted` 中调用并把
`viewportCleanup` 在 `onBeforeUnmount` 释放。

## 验证

> 原生改动必须重新构建 Android 包（`pnpm tauri build -- --target ...` / Android Studio）才生效，
> WebView 前端热更新不覆盖原生层。

验证清单：

1. 键盘弹出：输入框可见、页面底部被顶到键盘上方（不遮挡）；
2. 键盘收起：恢复全屏，无残留内边距；
3. 状态栏：顶部标题不被状态栏图标遮挡（`env(safe-area-inset-top)` 生效）；
4. 底部导航/底部输入栏：不被系统手势条遮挡（`env(safe-area-inset-bottom)` 生效）；
5. 会话列表、聊天页等其它依赖 safe-area 的页面顶部/底部均正常。

## 注意事项（坑）

- **禁止**在根部把 insets 整体 `CONSUMED`——会让整个 App 的 `env(safe-area-inset-*)`
  全部失效，表现为主机/模拟器上“状态栏和底部 bar 都顶到/压住内容”。
- 若只消费 IME、透传其余 insets 后仍出现内容比键盘“高出一截”（双重缩小），
  说明该机 `adjustResize` 同时生效：去掉其中一种处理（优先去掉前端固定高度或原生 padding 二者之一）再做取舍。
- `adjustResize` 在不同 Android 版本/厂商 ROM 行为不一致，最终以真机实测为准。
